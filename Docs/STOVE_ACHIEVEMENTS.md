# STOVE 도전과제 연결 및 등록표

구현 브랜치: `dev/stove`. **STOVE Studio 실제 등록은 사용자가 진행하며 완료 여부는 미확인이다.** 아래 `stat_id`는 코드의 스탯 전송 ID, `achievement_id`는 STOVE 자동 할당 도전과제 ID, `project_label`은 기존 프로젝트 관리용 이름이다.

기획 근거: [Notion 공통준비사항](https://app.notion.com/p/3fdc227fda03812fb239c2aecec78bfe). 사용자의 2026-10-23 확정 지시에 따라 기본 15턴뿐 아니라 **10·15·20턴 모두** 인정한다. 사용자 요청에 따라 2026-10-23 Notion 공통준비사항에 34개 도전과제 ID·Stat ID와 공통 등록 설정을 반영했다. Studio 실제 등록은 사용자가 진행하며 완료 여부는 미확인이다.

## 공통 집계 기준

- STOVE Release 빌드에서 4명으로 시작한 정식 온라인 경기를 정상 종료해야 기록을 확정한다. Editor, Development 빌드, Testbed, Solo, 자동화·강제 결과에서는 업적이 전송되지 않는다.
- 경기 중 기록은 호스트가 승인한 이벤트에서만 수집한다. 두 보너스 열쇠를 반영한 최종 순위 확정 시 각자의 계정에 확정한다. 공동 1위를 인정한다. 최종 확정 전 무효 경기는 누적하지 않는다.
- 미니게임 내부 라운드 우승과 미니게임 최종 우승은 구분한다. SKIP은 참가·우승 횟수에 포함하지 않으며 연승을 끊지 않는다.
- 구매 기록에는 무료 지급, 상자 획득, 보너스 열쇠, 강탈을 포함하지 않는다. 실제 결제 성공만 기록한다.
- 복구 체크포인트에 경기 ID와 플레이어별 임시 기록을 저장한다. 복구되면 체크포인트 이후 진행은 함께 되돌아간다. 기존 버전의 업적 기록 없는 저장도 플레이할 수 있지만 해당 경기는 업적에서 제외한다.
- 최종 결과를 재수신하거나 같은 완료 경기를 복구해도 동일 경기 ID는 한 번만 누적한다. 최종 확정 이후 대기실 복귀·게임 종료는 저장된 대기열을 지우지 않는다.

## 공통 스탯 29개

도전과제 34개를 유지하고 아래 5쌍을 공통 스탯으로 연결한다. 나머지 24개는 개별 달성 여부 0/1을 사용한다. 스탯 업데이트 타입은 모두 **MAX**, 도전과제 목표 방식은 모두 **이상**이다.

| Stat ID | 스탯 관리명 / 전송 값 | 도전과제 번호 | 목표 값 |
|---|---|---|---|
| `MP_ACH_01` | 누적 정상 완주 횟수 | 01 / 02 | 1 / 5 |
| `MP_ACH_03` | 누적 종합 우승 횟수 | 03 / 04 | 1 / 5 |
| `MP_ACH_07` | 열쇠 상점 누적 유료 구매 횟수 | 07 / 08 | 1 / 10 |
| `MP_ACH_12` | 아이템 상점 누적 유료 구매 횟수 | 12 / 13 | 1 / 10 |
| `MP_ACH_25` | 정상 완료한 한 경기의 미니게임 최고 우승 횟수 | 25 / 26 | 1 / 5 |

누적 횟수는 목표를 넘겨도 계속 저장·전송한다. 예를 들어 유료 구매 12회는 값 `12`를 보낸다. `MAX`는 기존 서버 값보다 작은 값으로 낮추지 않으므로 매번 `+1`을 보내지 않고 전체 누적값을 보낸다. 구매 횟수의 표현 한계는 SDK의 Int32 최댓값(2,147,483,647)이며 그 값에서 포화시켜 오버플로를 방지한다.

`MP_ACH_25`는 여러 경기의 승수를 합산하지 않는다. 한 경기 3승·다음 경기 2승이면 최고 기록은 `3`, 한 경기 5승이면 `5`다. 27번의 3연승과 09번의 한 턴 2회 구매 등 집계 범위가 다른 조건은 별도 스탯을 유지한다.

## Studio 등록

[공식 스탯 등록 안내](https://studiodocs.onstove.com/features/stats)와 [공식 도전과제 등록 안내](https://studiodocs.onstove.com/features/achievements)를 참고한다.

1. 상품 홈 → 프로젝트/상품 관리에서 상품 선택 → 상품 데이터 관리 → 스탯 → 등록으로 이동한다.
2. [STOVE_STATS.csv](STOVE_STATS.csv)의 **29개** Stat ID·업데이트 타입 `MAX`·관리명을 입력한다. `MP_ACH_02/04/08/13/26`은 별도로 등록하지 않는다. 다른 번호를 당겨 재배열하지 않으며, 기존 스탯을 이 작업에서 삭제하거나 초기화하지 않는다.
3. [STOVE_ACHIEVEMENTS.csv](STOVE_ACHIEVEMENTS.csv)는 도전과제 **34개**의 연결 Stat ID와 목표 값 표다. 상품 데이터 관리 → 도전 과제 → 등록에서 기존 스탯을 선택하고 `stat_id`, **달성 목표 값 `unlock_value`(1·5·10)**, **달성 목표 방식 이상**을 입력한다. 같은 스탯에 연결하는 과제도 각각 등록한다.
4. 도전 과제명·설명·미달성/달성 이미지를 입력하고 저장한다. 스토어 공개/숨김은 따로 저장한다. 아이콘 34쌍은 [StoreAssets/Achievements/2026-10-23](StoreAssets/Achievements/2026-10-23/README.txt)에 준비되어 있다.
5. CSV는 등록 참고표이며 Studio 일괄 업로드 양식이 아니다. 공식 양식에는 초기값·최소값·최대값 입력 칸이 없다. 도전과제 CSV의 `stat_initial/min/max`는 코드의 값 범위 참고이며, `stat_name_ko`는 스탯 관리명, `stat_value_source`는 코드의 집계 원본이다.
6. `achievement_id`는 STOVE가 자동 할당하는 도전과제 ID다. 사용자가 Notion에서 수정한 01~06번의 `스탯 ID_목표값` 형식에 맞춰 34개를 정리했다. 예: 첫 번째 시상식 `MP_ACH_01_1`, 파티의 단골손님 `MP_ACH_01_5`, 열쇠 상점 단골 `MP_ACH_07_10`. Studio의 ID를 직접 입력하거나 변경하는 작업이 아니다.
7. 기존 `MP_01_FIRST_CEREMONY` 등의 이름은 CSV의 `project_label`로 보존한다. `achievement_id_source=notion_user`는 사용자가 Notion에 적은 01~06번, `stat_target_rule`은 같은 형식으로 계산한 07~34번이며 Studio 실제 표시값과 대조가 필요하다. 이 구분은 등록·공개·현지화 저장·실계정 해제 완료 상태를 뜻하지 않는다.
8. 게임은 `Stove_SetStat`의 `StatsId`에 기존 `stat_id`를 보낸다. 자동 할당 도전과제 ID를 `StatsId`에 넣지 않는다. 스탯 29개·목표값·게임 판정·저장 데이터·아이콘 파일명은 유지한다.

SDK 3.5.3.0의 `Stove.PCSDK.V3.GameSupport.Stove_SetStat`에 실제 누적값·최고 기록 또는 달성 여부를 전달한다. 기존 Base SDK 초기화·콜백 펌프를 공유하며, 성공 응답의 `CurrentValue`가 **이번 요청에서 보낸 값 이상**일 때만 그 값을 전송 완료로 저장한다. 서버 값이 이미 같아서 변경되지 않은 성공 응답도 인정한다.

## 나머지 도전과제 · 등록용 현지화 (02~34)

2026-10-23 사용자 요청에 따라 33개 이름·설명의 en/ja/zh-Hans 현지화를 Notion 공통준비사항에 기록했다. 한국어 이름은 기존 기획을 유지하며, 한국어 설명은 번역 대조와 Studio 등록용이다. 첫 번째 시상식의 확정 문구는 위 표를 따른다.

공통 판정은 4인으로 시작한 정식 온라인 경기(10·15·20턴)의 정상 종료다. 모든 언어에 해당 과제의 같은 Stat ID와 목표 값을 사용한다. MAX·이상 방식이며 02·04·26번 목표는 5, 08·13번은 10, 나머지는 1이다. 미니게임과 아이템 이름은 현재 StringTable.csv를 기준으로 했다. Studio에서의 언어별 저장 완료 여부는 미확인이다.

## 저장·재전송과 범위

- `Application.persistentDataPath/Achievements/<STOVE 계정 범위>.json`에 누적 기록, 한 경기 미니게임 최고 우승 횟수, 완료 경기 ID, 스탯별 마지막 전송 확인값을 v2 형식으로 저장한다. 계정 범위는 채널·UGS 환경·STOVE 환경·게임 ID·STOVE 계정으로 분리한다.
- 임시 파일 flush 후 원자적 교체를 사용한다. 손상되거나 다른 계정의 파일이면 초기화하지 않고 해당 실행의 업적 처리를 중지하여 중복 집계를 막는다. 사용자 파일을 수동 삭제하면 미달성 누적 기록과 중복 방지 기록도 사라진다.
- 전송은 STOVE 권장 간격에 맞춰 전체 요청을 최소 60초 간격으로 한 개씩 진행한다. 20초 이상 응답이 없으면 만료 처리하고 다음 전송 시점에 다른 대기 통계로 진행한다. 여러 업적은 순차 반영되며 게임을 종료하면 남은 업적은 다음 로그인 뒤 계속 전송한다. 뒤늦은 이전 요청의 응답으로 새 요청이 완료되지 않는다. 응답 없는 네이티브 콜백이 8개 누적되면 재시작까지 추가 요청을 제한한다.
- 최종 결과는 시상식 동안 5초마다 재전송한다. 네트워크 끊김 때문에 최종 결과를 한 번도 받지 못한 참가자는 그 결과를 로컬 확정할 수 없다. 체크포인트를 통한 경기 복구는 동일 ID를 유지한다.
- 전송 대기 여부는 현재 값과 스탯별 확인값을 비교한다. 요청 중 새 경기가 완료되면 이전 요청 값만 확인하고 증가분은 다음 요청으로 보낸다. 같은 공통 스탯을 두 과제 때문에 중복 전송하지 않는다. 해제 후에도 횟수가 늘거나 최고 기록을 갱신하면 다시 전송한다.
- **공통 스탯의 진행값도 STOVE에 전송하지만, 누적의 원본은 현재 PC의 계정별 저장이다.** 다른 PC·재설치 간 누적 기록을 조회·합산하는 기능은 포함하지 않는다. 다른 PC에서 더 낮은 값을 보내도 MAX로 서버 값을 낮추지는 않지만, 두 PC의 기록을 합산하지는 않는다. Steam/개발 계정 기록을 옮기지 않는다.

### 기존 v1 저장 이전

- 기존 달성 비트, 완료 경기 ID, 완주·종합 우승·구매 기록을 보존하고 v2로 원자적으로 교체한다. 이미 확인된 개별 0/1 스탯은 유지하며 공통 스탯 5개는 실제 값으로 다시 동기화한다. 같은 경기를 재수신해도 재누적하지 않는다.
- v1은 구매 횟수를 10까지만 보관했다. 남아 있는 값부터 계속 누적하며, 이미 버려진 과거의 10 초과 구매 횟수는 복원할 수 없다.
- v1에는 한 경기 최고 승수가 없다. 기존 달성 기록으로 증명되는 하한인 첫 우승 1, 3연승 3, 한 경기 5승 5 중 가장 큰 값을 복원한다. 이후 정상 완료한 경기의 실제 승수로 최고 기록을 갱신한다. 이전의 정확한 2·4·6 이상 최고 기록은 복원할 수 없지만 기존 달성 여부는 유지한다.
- 파일 손상·계정 불일치·잘못된 확인값·저장 실패에서는 기록을 초기화하지 않고 처리를 중지한다. 하위 버전의 게임은 v2 저장을 읽지 못하므로 배포 버전을 함께 맞춘다. persist 경로의 파일을 수동 삭제하거나 초기화할 필요는 없다.
- 호스트가 승인한 결과와 로컬 계정 검증에 기반한다. 별도 신뢰 서버에서 STOVE 결과를 검증하는 부정행위 방지 시스템은 아니다.
